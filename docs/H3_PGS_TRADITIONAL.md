# H3 测试流：传统二采极速 + 小脸修复

工作流：`examples/H3测试流-传统二采极速-小脸修复.json`。同名文件已保存到 ComfyUI 的工作流目录，原始【H3测试流】不变。

模型、人物图、场景图、原提示词、源视频分段计划沿用【H3测试流】；LoRA 和采样配方来自【H3双采流-传统-极速流】。

| 阶段 | 默认配置 |
| --- | --- |
| 模型 | 原流所选 Dasiwa Hybrid V4 INT8、Qwen3-VL NVFP4、普通视频 VAE、音频 VAE |
| LoRA | DMAD v4 step600 + character_swap v1.1，强度均为 1 |
| Sigma Shift | 视频 12 / 音频 2 |
| 最终尺寸 | 分辨率控件默认 768p，1344×768 |
| 首采 | 最终宽高各乘 0.5 后向下按 32 对齐；4 步 Euler / simple，denoise=1 |
| 传统放大 | `minimax_h3_latent_upscaler_3d_fp16.safetensors`，目标为最终宽高 |
| 二采 | SA Solver；Sigma `0.631578922, 0.3158, 0`，2 步；FFN 分 8 块 |
| 小脸修复 | 默认开启，1 人；同一模型与 LoRA；Sigma `0.631578922, 0.3158, 0`；人物参考只接 Picture 1 |

最终宽高在最左侧设置。双击“LoRA 与模型优化”可选择两个 LoRA；两项强度也可在子图外直接修改。双击首采子图可查看调度器和采样器；传统放大、二采、修脸均为独立模块。

## 上下文顺序

首采参考编码 → 首采上下文 → 首采 → 首采接缝对齐 → 保存低分 Latent → 传统放大 → 二采 → 二采接缝对齐 → 保存高分 Latent → 视频 / 音频解码 → 小脸修复 → 裁掉重叠 → 保存视频。

二采使用独立的最终尺寸参考编码和上下文条件。首采、二采均沿用原流 PGS guide 模式，视频上下文 22 帧，音频上下文 18 帧。

- 首采从 `output/h3_pgs_traditional_fast/low` 读取并保存。
- 二采从 `output/h3_pgs_traditional_fast/high` 读取并保存。
- 当前索引读取上一段；当前索引加 1 保存本段。循环从 0 开始，首段没有历史 Latent 时自动跳过上下文；默认运行前两段。
- 循环终点等待两路 Latent 及视频全部保存后才进入下一段，避免读取尚未写完的文件。
- 接缝数值对齐位于各自采样之后。高分 Latent 在修脸之前保存，修脸后的 RGB 不重新编码进入上下文。
- 第二段开始，图片帧和音频同步裁去 22 帧对应的时长。

视频输出前缀：`video/H3测试流-传统二采极速-小脸修复`。沿用原视频每段 175 帧的计划时，首段输出约 7.29 秒，第二段裁掉重叠后输出约 6.38 秒。调整视频分段数量后，同时调整循环停止值；该值不包含在循环范围内。

## 实测

2026-11-01：在独立浏览器中加载、保存并重新加载，导出的执行图保持一致，所有节点可用。随后在本机 ComfyUI 实际运行两段，使用原人物图、场景图、视频和提示词，只将最终尺寸改为 768×448、每段输入缩短为 56 帧；首采 4 步、二采 2 步、修脸 2 步均保持完整。

两段均成功完成，第二段实际读取两种分辨率的历史 Latent，接缝对齐触发自动修正。四份缓存中的视频 Latent 尺寸分别为 24×14 和 48×28，均保留音频流。FFprobe 验证两个 MP4 都有视频和音频，24 fps，分别为 56 帧和 34 帧，确认裁掉 22 帧重叠。

两段合计约 115 秒，观察到的显存峰值约 44.37 GiB；这是短片连通性测试数据。默认 1344×768、175 帧分段尚未完整实跑，不能据此推算其耗时、峰值显存或长期接续色差。
