# 人物替换配置与循环保存

提供 LLM 通用连接器、人物替换配置器、配置解析器与循环视频保存节点。配置器分为“媒体输出”和“配置输出”两种：前者直接输出指定片段的媒体，后者输出整份配置，交给解析器按索引提取媒体。

## 配置器与接线

配置器左侧上方放一个视频，下方放六张参考图；支持文件选择、拖拽和选中节点后 Ctrl + V 上传。图片完整显示，保留各自比例与尺寸；图片缩放倍率分别作用于每张图片。空图片槽不会输出。

左侧媒体区从输入接口下方开始，图片下方设置分辨率、时长、比例与图片缩放倍率。右侧查看、编辑每段提示词。未连接“当前索引”时，媒体输出配置器输出面板选中的片段，包括视频、提示词、尺寸、时长和片段序号；所选片段随工作流保存。连接“当前索引”后，以外部索引为准，面板选择不影响循环执行。配置输出模式会把所选片段一起交给配置解析器，解析器遵循相同规则。

| 接口 | 含义 |
| --- | --- |
| 当前索引（输入） | 可选 INT 连线输入，从 **0** 开始；未连接时使用面板所选片段，连接后优先使用外部整数或循环索引 |
| LLM 连接器（输入） | 可选；手动优化或自动优化时需要 |
| 图片列表 | 按非空槽顺序排列的 IMAGE 列表，各图尺寸可以不同 |
| 视频列表 | 长度为 1 的 VIDEO 列表，只包含当前段 |
| 提示词 | 当前段使用的优化后提示词；没有有效优化结果时使用原始要求 |
| 宽度 / 高度 | 当前输出视频经过裁剪、比例、压缩尺寸和对齐后的实际像素尺寸，INT 类型 |
| 长度（帧数） | 当前输出视频的实际帧数，INT 类型；尾段按实际剩余长度返回 |
| 时长（秒） | 实际帧数除以输出帧率，FLOAT 类型；可直接连接全模态生成节点的时长 |
| 片段序号 | 当前索引 + 1，从 **1** 开始，连接保存器 |
| 片段总数 | 当前计划的总段数，连接保存器和外部循环判断 |
| 项目目录 | STRING 目录：`video/人物替换/%date:yyyy-MM-dd%/{视频名称}/`；视频名称取源视频文件名，不含扩展名 |

媒体输出配置器与配置解析器都提供“项目目录”。连接保存器的“保存目录 / 前缀”后，日期在保存时展开，片段按日期和源视频分别归档。

配置器和保存器都由外部工作流调度。外部循环可将配置器的“片段序号”回传为下一轮的“当前索引”，在“片段序号 < 片段总数”时继续。保存器的“待保存视频”接生成结果，“片段序号”和“片段总数”接配置器对应的整数输出；右侧“视频”在保存完成后传出输入的视频，可接入循环结束节点，确保每轮先完成保存。

对于人物替换，将配置器的提示词、图片列表、视频列表接到全模态生成节点，再将生成的视频接到保存器。列表应接收列表的接口；普通 IMAGE 接口会按 ComfyUI 的列表规则逐项执行。

可导入 [人物替换-外部循环分段接线示例](../examples/人物替换-外部循环分段接线示例.json)。示例使用已安装的 PGS While 循环，直接保存原视频的分段，用于验证索引与保存接线。实际生成时，把配置器到保存器之间的视频连线替换为全模态生成链路。

### 官方循环自动段数

使用官方 `StartLoop / EndLoop` 时，将 **人物替换配置器 · 配置输出** 放在循环外。它沿用相同的媒体与提示词编辑面板，只读取视频元信息计算段数，不提前转码片段或调用 LLM。

- 配置器的“片段总数”连接 `StartLoop.max_iteration`，起始索引为 0、步长为 1。
- 配置器的“分段配置”连接循环内的 **人物替换配置解析器**，循环索引连接其“当前索引”。
- 解析器输出的图片、视频与提示词送入生成节点；片段序号送保存器，配置器的总数送保存器。
- 保存器的视频同时连接 `EndLoop.output_value` 和 `next_iteration_value`；`StartLoop.current_iteration_value` 接生成节点的上一段视频。
- `StartLoop.is_first` 取反后控制上下文开关，首段关闭，后续开启。

这样处理完实际段数后自然结束，并确保每轮保存完成后再开始下一轮。不要把依赖循环索引的解析器输出倒接循环开始，否则会形成依赖环。当前官方循环没有条件 `break`；`terminations` 用于保证每轮执行指定输出，不是结束条件。

## 视频编辑与分段

视频右上角“编辑”打开内置编辑器，可调整压缩尺寸、帧率、时间范围、画面裁剪与分段计划。保存才应用编辑；取消保持当前配置。

仅调整参考视频的压缩宽高、缩放比例或编码质量时，保留已优化的提示词，共用与各片段的内容均不会清空。改变片段时间范围、分段安排或画面裁剪后，需要重新优化。

- 未启用分段计划时，左侧每段时长可选 5、10、15 秒，也支持小数自定义。
- 启用计划后，左侧时长显示计划中的实际帧数，修改入口统一在编辑器内。
- MiniMax H3 模式按 24 fps，提供合法总帧数和上下文重叠帧选项。
- 普通模式按秒配置，支持小数时长。
- 编辑器的“切分方式”可选“按镜头切分”：点击“检测镜头”后，使用 PySceneDetect 的自适应或画面差异检测找到原视频切镜点。切换方式、修改参数和重新打开编辑器不会自动检测；已有检测结果直接用于重新计算分段。过短镜头可在时长允许时合并，超长镜头在自身范围内分段。
- 上方分段条的分界可左右拖动，按帧调整相邻片段长短，画面同步定位到分界处。调整保留上下文重叠和整体选择范围；手动段长可超过自动分段的段长设置。保存后实际生成使用调整后的边界，取消不应用；修改分段参数或选择范围后重新计算分段。
- “最短镜头（秒）”控制短镜头合并，“灵敏度”越高越容易检出切镜。检测只分析原视频，不使用 LLM 或生成模型；分段计划随工作流保存，预览与实际生成使用相同边界。配置解析器在真正的切镜处关闭上一段上下文，同一镜头内的续段仍可承接。

镜头切分参考 [BFS Shot Planner](https://github.com/alisson-anjos/ComfyUI-BFSNodes) 的处理思路，由本包独立接入 PySceneDetect，不需要安装 BFS 节点包。MiniMax H3 模式仍保留合法段长上限与重叠选项；切镜点按原视频准确保留，较短片段沿用现有生成节点的帧数对齐处理。
- “完整片段”包含重叠区，下一段起点前移相应重叠帧数。例如 175 帧、重叠 22 帧，片段依次从第 0、153、306 帧开始。
- “仅新增片段”按目标帧数连续切分，输出中不附带重叠前缀。

尾段以原视频剩余帧数为准，不补出不存在的内容。完整片段模式下，剩余长度不超过重叠长度时不再生成只有重叠内容的片段。分段模式统一使用 24 fps，宽高按 H3 所需对齐到 32 的倍数。

“完整片段”的重叠是送给生成节点的参考视频区间；保存器按收到的视频完整拼接，不额外推测或裁除上下文。使用带上下文的生成流程时，应让生成节点输出仅新增画面后再送入保存器。

## 提示词与 LLM

提示词编辑支持素材引用标签、对白标签、纯文本切换和当前段抽帧预览。`@图片3` 始终指向第 3 个图片槽；输出时按非空槽映射为 `<Picture N>`。例如仅第 1、3 槽有图时，`@图片3` 输出为 `<Picture 2>`。

“优化”左侧的齿轮按钮打开 Skill 编辑窗口。顶部“重置为默认”恢复内置规则到编辑框，底部“保存”后才生效。规则持久保存在 ComfyUI 的 `user/yton-replacement-skill.md`，供人物替换节点的手动与自动优化共用；关闭窗口不保存草稿。修改并保存 Skill 后，旧规则生成的优化结果失效，原始要求保留。

原始要求与优化结果分别保存。点击“优化”会将当前段六帧拼图、已上传参考图与用户要求交给视觉模型，默认生成“主体替换、角色外观、背景、同步要求、负面提示”五部分提示词；自定义 Skill 可改变提示词结构与写法。图片可以表示角色，也可以表示背景等参考信息。

“全段共用提示词”开启后，全部片段使用同一份原始要求和优化结果；仍可切换片段查看各自帧数、时长和抽帧内容，切换不会改变共用提示词。关闭时按片段编辑。共用模式与各片段分别保存原始要求和优化结果，切换模式只恢复对应内容，不自动复制或覆盖另一种模式的内容。“每段自动优化”会在执行当前段时调用 LLM；与共用开关同时开启时，一轮循环只优化一次。重新提交工作流会重新优化。素材或相关配置变化后，手动优化结果会失效，原始要求保留。

LLM 通用连接器选择服务与模型，设置默认温度和最大输出长度；模型需要支持图像输入。服务设置与已有提示词优化器共用 `yton-ai.json`。API 密钥保存在服务器侧，不写进工作流。

其他节点可接收同一个 `YTON_LLM` 类型，由任务节点提供指令、图片和调用参数：

```python
io.Custom("YTON_LLM").Input("llm")

text = llm.generate(
    "用户要求",
    system="当前任务的系统指令",
    images=[pil_image],
    parameters={"temperature": 0.4},
)
```

任务调用可覆盖 `temperature`、`max_tokens`、`top_p`、`seed`、`response_format`。连接器本身不预设人物替换任务。

## 保存与预览

每轮将片段保存到 ComfyUI 的 output 目录下，按运行标识隔离，并记录 `segments.json`。相同运行内重复保存同一索引会替换该段。所有片段到齐后才按索引顺序合并。

每次保存向 ComfyUI 回报当前片段的标准视频输出；完整视频持久保存后也回报为输出，使其出现在任务历史和资产面板。完整成片文件名为 `complete.mp4`，与该轮片段保存在同一目录。

支持 MP4/MKV（H.264）、帧率与 CRF。各段统一尺寸、帧率和音频格式，无音频片段补静音。上方播放合并视频，下方只展示各片段；点击片段可单独预览，标题旁的返回图标用于切回完整视频。

关闭“保存完整视频”时，各片段仍永久保存，合并成片只生成到 ComfyUI 的 temp 目录供预览。临时文件可能被清理；需要保留成片时开启该开关。

## 编辑器来源与独立性

视频编辑器参考本机 `ComfyUI-LoadRef-PGS/web/js/video_editor.mjs` 与所需工具；提示词编辑器参考 `ComfyUI-MiniMaxH3-Ref-PGS/web/pgs_rich_editor.mjs` 及所需样式与工具。本实现将所需代码内置于 `web/js/replacement/`，并隔离 CSS 命名。运行时不加载这些插件，人物替换节点可以独立使用。示例中的外部 PGS 循环节点需要对应循环插件。

## 验证

`tests/test_character_replacement.py` 使用 CPU 合成短视频验证真实裁剪、分段、音频、保存合并与原生 PGS 循环执行；`tests/replacement_browser_checks.js` 在隔离浏览器中验证上传、编辑、引用、优化、序列化和成片播放，不提交真实 H3 生成任务。
