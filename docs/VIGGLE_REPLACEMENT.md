# Viggle 人物替换

新增节点位于 `yton-nodes/Viggle`：

- **Viggle 人物替换配置器 · 配置输出**：视频编辑与分段、四图参考、四个替换关键帧、片段提示词及 LLM 优化。
- **Viggle 人物替换配置解析器**：把当前段拆成原始视频、提示词、四张独立参考图、pins、短边尺寸和片段信息。
- **Viggle 视频长度调整**：同一节点可在生成前适配 H3，也可在生成后恢复源视频时长。

## 交互

参考图模式固定四个等大槽，空槽、部分上传、全部上传均保持尺寸。图片支持标题按钮上传、拖拽到具体槽，以及选中节点后 Ctrl + V；点击图片槽后粘贴会替换该槽。

关键帧模式在左侧直接操作当前段。拖动方形帧轨道查看视频，按 C 或点击锁定按钮收集当前帧；每段最多四个。轨道保留所选帧标记，标记可拖动调整位置。列表按时间排序，每组左原帧、右替换图，列表最高显示两组并使用 3px 滚动条。上传与使用重叠帧在标题行，原帧右下角悬停下载，文件名为 `原视频名_第N帧.png`。界面帧号从 1 开始，实际 pins 从 0 开始。

选择 5 帧上下文后，后续段开头包含前段末尾的 5 帧。对应关键帧标题行的“使用重叠帧”直接从下游循环保存节点中查找上一段生成结果，按源时间对应取帧并填入；无需选帧弹窗。须先保存上一段，且保存节点连接在此配置器下游。四个槽位均由用户选择。

## 连接官方工作流

1. 配置器“本段配置”连接配置解析器。
2. 解析器“原始片段”与“片段信息”连接生成前的视频长度调整；模式选“适配 H3”，上下文与配置器保持一致。
3. 长度调整“视频帧”“音频”“长度（帧）”分别连接官方 Viggle Remake Conditioning 的 `source`、`audio`、`frames`。
4. 解析器“参考图 1–4”“pins”“提示词”“短边尺寸”分别连接 Conditioning 的 `ref_1–ref_4`、`pins`、`prompt`、`short_edge`。其余模型、VAE、CLIP、采样与解码沿用官方工作流。
5. 将解码后组成的 VIDEO 连接第二个视频长度调整，模式选“恢复原长度”。将生成前的“长度信息”连接到这里；两边选择相同上下文。
6. 恢复后的“视频”连接“人物替换 · 循环视频保存”。解析器“片段序号”“片段总数”“项目目录”连接保存节点的相应输入。

开启“从当前段循环到尾”后复用现有循环保存机制，依次执行当前段到尾段。自动优化使用当前段实际图片；普通参考模式输出空 pins，关键帧模式按时间排序已上传的替换图，并输出与图像顺序严格对应的零基 pins。没有上传替换图的空占位不进入生成输入。

生成前统一为 24fps，只在末尾重复最后一帧，补到 `17n+5`，最少 56 帧、最多 345 帧。原有帧的位置保持不变，音轨尾部补静音。恢复时先裁去补帧，再去除后续段开头的重复帧；首段保留开头。长度信息由连线传递，避免手工重新计算。

“使用重叠帧”既支持完整生成结果，也支持已恢复长度的已保存结果，定位依据是源时间范围，排除尾部补帧。循环过程中，对于用户已选择使用上一段的关键帧，会重新提取本轮上一段的对应画面。

## 验证

使用 `F:\ComfyUI\python\python.exe tests/test_viggle.py` 检查补帧、音轨、恢复、pins、重叠位置以及真实执行器的循环保存与合并。

先启动 `tests/viggle_preview_server.py`，再使用 Playwright 运行 `tests/viggle.browser.js`，可在独立浏览器上下文检查真实节点与 CPU 媒体接口。测试不会提交模型任务或改动当前工作流。
